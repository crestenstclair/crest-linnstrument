    Perform with the instrument

    • Expressive part: choose Play; place independent fingers, move X/Y and change pressure.
    • Chord progression: choose Chords; set Root and Scale above the instrument, select quality, extension and voicing controls in its compact left-hand block, then play the single degree/octave bank on the right.
    • Picked accompaniment: choose Strumplate; select I–VII on the top-right row and pick the labeled tones below.
    • Loop performance: prepare a recorded or generated phrase, launch it from a bottom-row Clips pad, then return to Play for a live part. Mute, octave and Fill pads make temporary changes.
    • Recording and session work: open Tools only to record, finish a take, configure the generator, edit notes and save. Close Tools to return to the surface. Input/device options stay collapsed during playing.

    Sound and Crest Synth integration

    • The library owns musical events, clips, harmony and controller behavior. Crest Synth is the eventual production sound engine behind its MIDI receiving boundary.
    • The current standalone simulator captures notes and expression. It has no built-in sound engine. These videos are visual demonstrations with captions and no audio.
    • Production instrument selection, sample playback and audible parameter mappings belong to the consuming host and Crest Synth. A captured parameter value does not establish an audible effect.

    1. What you can do

    Crest Performance lets you play expressive notes and chords, record them as loops, generate accompanying parts, and bring those parts in and out during a performance. You can use the on-screen LinnStrument with a mouse and keyboard; a physical instrument is not required.

    The current standalone application has eight clip slots. Each clip can contain a complete polyphonic phrase, including its pitch bends, pressure changes and tone-control gestures. Several clips can loop together while you play a new part.

    Sound in this release: the standalone desktop records and displays musical output but has no built-in instrument or sound-preset browser. The examples below produce notes and control data. To hear them, connect a compatible software or hardware instrument through the MIDI host. That instrument determines the sound. Parameter locks and A/B morphing currently produce diagnostic values only.

    What can you play?

    • An expressive lead over loops: record a chord phrase, loop it, then return to ordinary notes and play a melody with bends and vibrato.
    • A one-finger chord progression: choose C major and play I–VI–IV–V to produce C–Am–F–G. Change the voicing without changing the progression.
    • A repeating arpeggio: hold one chord pad to repeat its tones; release it to stop. Record the result as a loop.
    • A bass part that follows chords: generate a low chord-tone pattern and enable harmony following. Change the chord while the rhythm continues.
    • A picked chord melody: select Strumplate and choose individual chord tones in your own order and rhythm.
    • A layered performance: run several clips, bring in a Fill-conditioned part, mute the bass for a break, then restore it without restarting its loop.

    Current limits that affect performance

    • Eight clip slots and a shared budget of 15 sounding notes, including live chords, clip playback and sustained notes. A five-note chord consumes five of those notes.
    • One active surface mode at a time. Clip pads controls the performance; return to Play mode or Chord pads to play notes. Loops continue through the change.
    • No bundled sample instruments, granular playback, audio recording, arrangement timeline or external MIDI Clock synchronization.
    • The released desktop package is Linux x86_64. Steam Deck and physical-device qualification are not complete. This guide describes the standalone v0.4.0 application; Crest Tracker integration is separate.

    2. Choose a playing mode

    Three buttons at the top of the host change what the instrument's pads do. Chord pads also has a Playing choice inside Harmony: one-pad chords or Strumplate. Strum, arpeggio and humanization change how a chord is played; they are not additional surface-mode buttons.

    The two windows in the released v0.4.0 UI

    • Instrument window: the on-screen LinnStrument. Click or hold keyboard keys to place fingers; move them to shape notes. Colored dots show the instrument firmware's lights. Numbered rings show your virtual fingers.
    • Host window: the clip bank and musical controls. Select modes, configure chords and patterns, record, edit and save here.
    • Use the desktop window switcher or the application's Window menu to move between them. The host scrolls to reveal more panels.

    Change modes during a performance

    1. Finish or cancel any take in progress.
    2. Release held fingers, then choose the required mode in the host.
    3. Wait for the instrument's mode label to update before pressing another pad.
    • Changing mode releases live and generated notes; running clips continue.
    • To improvise over a launched phrase, launch it in Clip pads, then switch to Play mode.
    • To change a chord articulation from the controller, select it in Clip pads, then return to Chord pads and play a new chord.
    • There is no simultaneous arbitrary clip zone and expressive playing zone in the current layout.

    Terms used in this guide

    • Clip: a recorded or generated phrase that can loop. It can hold many notes at once.
    • Slot: one of the eight places in the clip bank.
    • Degree: a position in a scale, numbered I–VII. It selects the chord built on that scale note.
    • Voicing: the octave placement and order of a chord's notes.
    • Articulation: how the notes of a chord start and repeat.
    • Expression: changes you make after a note starts, such as bending its pitch or changing pressure.
    3. First performance: play, capture, launch

    Start the standalone application using Appendix A. Confirm FIRMWARE CONNECTED in the instrument window. For this first exercise, use the default 120 BPM and Launch grid: Off · immediate.

    Record your first phrase

    1. In the host, select an empty clip slot and choose Play mode.
    2. Select Record selected. Recording starts immediately.
    3. In the instrument window, press and release a few pads. Drag a held finger sideways for a bend; use the wheel to change its pressure. Alternatively, select Play scripted phrase to use the supplied three-finger example.
    4. Release all fingers. Return to the host and select Finish take.
    5. Click the selected recorded slot to start its loop. Its state becomes PLAYING; MIDI capture changes as the notes repeat.
    6. Select Clip pads. The first eight playing pads along the bottom row correspond to slots 01–08. Press your clip's pad to stop it; press again to launch it. Green means playing; blue means recorded and stopped.
    7. Return to Play mode and play another part over the loop.
    8. Use Stop all when finished. Save the session using Saving your work.
    Commit before stopping: Finish take keeps the new phrase. Stop all and Cancel take discard an unfinished take. The recording includes time spent switching windows, so the resulting loop may include a gap.

    Choose the next performance exercise

    • Chord progression: use the C–Am–F–G exercise, record it into one clip, then play a melody over it. All the chord tones stay together in that clip.
    • Repeated chord pattern: choose Arpeggio low to high, hold a chord pad, and record the result. The clip retains the notes and timing you performed.
    • Following bass: use the five-pulse bass recipe. Let the chord clip supply its harmony while the bass keeps its own rhythm.
    • Live variation: hold mute for a break, hold octave up for a temporary register change, or hold Fill to admit a prepared extra note. Release the control to return to the ordinary playback rule.

    Explore the supplied three-part session

    1. Save anything you want to keep before replacing the current session.
    2. At the bottom of the host, enter the absolute path to examples/performance-showcase.json from the package or source checkout. Select Reopen.
    3. Launch slot 01, the expressive chord phrase, and slot 02, the following bass. To launch a host slot, click it once to select it and again to start it.
    4. Launch slot 03. Its accompaniment notes are Fill-conditioned: hold Hold Fill to admit their next attacks.
    5. Try Hold mute selected on the bass, then release. Try Hold octave up on a running part. Neither operation rewrites its stored notes.
    6. Switch to Clip pads to operate the same performance from the instrument. See the pad reference for the hold controls.

    This supplied session uses three separate output destinations, all captured in the standalone host. The command-line MIDI host supports only destination 1 and cannot audition this multi-destination example unchanged.

    4. Play expressive notes

    Play mode gives you direct control of individual notes. Use it for a melody with bends and vibrato, a bassline, or chords whose tones you want to shape separately. A virtual finger is a held contact on the surface; several fingers can remain active together.

    Shape a note

    • Sideways movement: changes pitch. Small back-and-forth movement produces vibrato; a longer movement produces a bend or slide.
    • Vertical movement: sends an independent tone-control gesture. A connected instrument may use it for brightness or another assigned parameter.
    • Pressure: changes the pressure message for that note. A connected instrument decides whether it changes loudness, brightness or another sound parameter.
    • Several fingers: each note has its own expression. For example, sustain two chord tones while bending a third.

    MPE (MIDI Polyphonic Expression) carries these independent gestures to a compatible instrument. The current standalone host captures them even when no sound instrument is connected. The exact audible response depends on the receiving patch.

    Try independent expression with a mouse

    1. Enable Latch new fingers and click three different pads.
    2. Select one contact by its number. Use Left/Right arrows to bend it while the others remain held.
    3. Select a second contact and use Up/Down arrows for its vertical gesture.
    4. Select the third and use [/] or the Pressure slider to change only its pressure.
    5. Select Release all to clear the fingers.

    Pressure envelopes

    1. Release all contacts and stop any contact script.
    2. Expand Mouse / keyboard pressure profile.
    3. Set Attack ms and Release ms, each 0–2000.
    4. Select Apply pressure profile.
    • Attack controls how quickly pressure rises after a press; Release controls how quickly it falls after release. These are simulated finger-pressure changes, not a synthesizer’s audio envelope.
    • A value of 0 applies pressure or release immediately.
    • The profile applies to mouse, keyboard and scripted contacts.
    • Release All and focus recovery bypass the release ramp. At contact capacity, a new contact may retire the oldest already-released tail; held contacts are not stolen.

    Keyboard mapping

    The default A/S/D/F/G/H/J/K keys hold eight separate contacts. To change their pad positions, expand Keyboard contacts and edit the mapping while no fingers are held. Appendix C gives the mapping format. Load defaults restores the standard layout.

    Pedals

    • Hold left pedal and Hold sustain pedal operate emulated foot-switch pins.
    • Hold with the pointer, or focus a button and hold Space/Enter. Release ends the switch press. Focus loss releases both switches.
    • The right pedal defaults to sustain. Firmware settings determine pedal assignments.
    • Sustain extends note ownership and can consume the remaining voice budget. A released sustained note retains its last expression.
    5. One-pad chords and voicing

    Chord pads turns a single pad press into a complete chord. Choose a tonic and scale, then play degrees I–VII to build a progression. This is the implemented equivalent of the one-key diatonic chord idea in Orchid Key Mode.

    • Tonic: the home note of the key. Tonic MIDI 60 is middle C.
    • Scale: determines the notes used to build each degree's chord. Major, Natural minor, Dorian and Mixolydian are available.
    • Diatonic: the chord is built from the selected scale. You do not need to enter its individual tones.
    • Learned chord: an optional fixed voicing replaces the automatically built chord for one degree.

    The scale setting governs harmony and following parts. It does not turn Play mode into a separate scale-only keyboard; Play mode continues to provide ordinary notes.

    Example: C–Am–F–G with four pads

    1. Start with an unused degree bank, or restore any learned entries you will use to diatonic.
    2. In Harmony, set Tonic MIDI: 60, Scale: Major, Playing: Chord pads, Chord: Triad and Articulation: Together.
    3. Set Suspension to None, Inversion and Register to 0, and turn off borrowing, spread and voice leading. Leave Input anchor at 30. Select Apply harmony, then Chord pads in the toolbar.
    4. With the default instrument tuning, the first seven playing pads of the bottom row select I–VII. Press columns 1, 6, 4, 5 in sequence, releasing between chords. These produce C, Am, F, G.
    5. Record the progression into one clip. Try another take with a different inversion or articulation.

    If you changed the firmware's tuning or transposition, restore its defaults or adjust Input anchor to match the incoming note used for degree I. The degree mapping follows incoming pitches.

    Change the chord without changing its degree

    • Seventh / Ninth: add further scale tones. On degree I in C major, these give C–E–G–B and C–E–G–B–D.
    • Sus2 / Sus4: replace the chord's third with the second or fourth scale step. C major becomes C–D–G or C–F–G.
    • Borrow parallel minor/major: use the parallel scale for the selected chord. For example, degree IV in C major becomes F minor when borrowed from C natural minor.
    • Inversion: move notes across octaves while keeping the chord tones. C–E–G can become E–G–C.
    • Open spread: lift the second voice by an octave to widen the chord.
    • Register: move the entire voicing up or down by octaves.
    • Voice leading: choose nearby octave placements to reduce movement between successive voicings.

    Settings apply to new chord attacks. A held chord keeps the notes it started with. The separate bass option uses the chord root below the main voicing; changing inversion does not make the bass follow the new lowest chord tone.

    • All chord voices: your finger's bend, vertical gesture and pressure affect every generated chord tone together.
    • Top voice only: shape the highest chord tone while the lower tones retain their initial expression.
    • Release the triggering finger to release its whole chord. A chord on another finger retains its own expression.

    Learn a fixed voicing

    Use learning for a voicing you want to recall with one pad, including a chord outside the selected scale. The seven degree positions can mix learned chords and automatically built chords.

    1. Finish/cancel recording. Select a slot on the intended input track.
    2. Choose Play mode.
    3. Latch 1–5 notes on the instrument.
    4. In Harmony, choose the target degree I–VII.
    5. Optionally enter Learned root MIDI. Leave blank to use the lowest held key.
    6. Select Learn held notes to selected degree.
    7. Release the fingers, switch to Chord pads, and play that degree.
    • Learning uses live notes on the selected slot's track. It preserves fixed MIDI pitches and unisons; current pitch bends do not change learned keys.
    • The explicit root supports rootless voicings and routed bass.
    • Tonic, scale, extension and borrowing do not rewrite learned pitches.
    • Inversion, spread, register, voice leading, articulation and expression still apply.
    • Restore selected degree to diatonic clears only that bank entry. Learning and restoring support Undo.
    • The bank has seven entries. Empty entries use diatonic harmony.
    6. Strum, arpeggio, humanization and Strumplate

    Articulation controls how a held chord is played. Use Together for simultaneous chord notes, Strum for a single spread-out attack, Arpeggio for a repeating pattern, or Humanized for small timing and velocity differences.

    Set Articulation in Harmony and select Apply harmony. These settings apply to new chord triggers.

    ArticulationBehaviorRelevant settings
    TogetherAttack the voiced chord as a block.Voicing and expression policy.
    Strum low to high / high to lowSchedule each voiced tone in pitch order at fixed beat intervals.Step spacing: 1/32, 1/16, 1/8, 1/4, 1/2 or 1 beat.
    Arpeggio low to high / high to lowRepeat the trigger's original voiced chord while held. Release the pad to stop the repetition.Step spacing; gate from 1/64 to 1 beat. Gate must not exceed spacing.
    Humanized chordSlightly delay individual chord tones and vary their attack strength. The seed makes these variations repeatable.Delay 0–960,000 ticks; velocity variation 0–63; UI seed 0–4,294,967,295.
    • Release the trigger to cancel waiting/future attacks and release its sounding voices.
    • X/Y/Z follows the trigger under the selected all/top-voice policy. Upcoming tones begin with the retained expression state.
    • Bass attacks immediately and remains held; manual Strumplate notes remain immediate.
    • Recording stores rendered timing, gates and velocities. Loop playback does not draw new random values.
    • Controller articulation selectors preserve custom timing when changing direction within a family. Entering a different family uses 1/16-beat steps, 1/32-beat arpeggio gate, or humanization delay 1/16 beat, velocity variation 8 and seed 42. Reselecting the current family retains custom settings.

    Example: strum or arpeggiate the same chord

    1. Use the C major chord setup above and hold the degree-I pad.
    2. For a strum, release the pad, choose Strum low to high and Step spacing: 1/8 beat, then Apply harmony and press it again. C, E and G begin in sequence; the chord does not keep retriggering.
    3. For an arpeggio, release, choose Arpeggio low to high, Step spacing: 1/2 beat and Arpeggio gate: 1/4 beat. Apply and hold the pad. C–E–G repeats until release.
    4. Record either result to keep that performance in a clip.
    • Step spacing: time between notes. One beat is a quarter note; 1/2 beat gives eighth-note spacing.
    • Gate: how long each arpeggio note stays on. A shorter gate leaves more space between notes.
    • Humanize delay: the maximum extra delay for a chord tone. At 120 BPM, 60,000 ticks is 31.25 ms.
    • Velocity variation: the allowed change in attack strength. Its audible effect depends on the connected instrument.
    • Seed: the number used to reproduce the variation. Recording keeps the performed result; playback does not choose new variations.

    Manual Strumplate: pick chord tones yourself

    Strumplate maps the playing pads to successive tones of one selected chord. For a basic C major voicing, successive input steps produce C–E–G, then C–E–G in the next octave. Choose the order and rhythm yourself. This is the implemented chord-tone picking feature related to the Omnichord strumplate.

    1. Choose a degree and voicing in Harmony.
    2. Set Playing to Strumplate, then Apply harmony.
    3. Enter Chord pads mode.
    4. Press successive instrument pads to pick successive chord tones across octaves. Sweep separate attacks for a manual strum.
    • A continuous firmware slide retains its existing note ownership and pitch bend. Sliding does not manufacture additional harp attacks.
    • Strumplate is an alternative whole-surface playing interpretation. It does not create simultaneous arbitrary custom chord and MPE zones.
    • Return to Play mode for ordinary notes.

    Choose harmony with the host's I–VII controls, then pick notes on the instrument. In the current layout, selecting harmony and playing the strumplate are separate operations; there is no dedicated simultaneous left-hand chord zone. A single continuous drag bends its existing note. Use separate pad attacks for separate picked notes.

    7. Generate accompaniment and follow harmony

    Accompaniment creates a clip from a rhythm and a bounded selection of chord tones. Harmony following lets that clip change pitch with a live chord or recorded progression while retaining its rhythm. Use these features for a bass ostinato, repeated chord-tone melody or additional rhythmic layer.

    How the parts work together

    • Harmony source: the chord that other parts follow. Choose Live / selected chord, or a recorded chord clip.
    • Follower: a clip with Follow harmony enabled. Its future notes adapt to that source; notes already held keep their pitch.
    • Euclidean rhythm: distributes a chosen number of attacks across a loop. For example, five pulses over sixteen steps creates five attacks spread across the bar.
    • Pitch cycle: controls the repeating pattern of tone choices independently of the rhythm's length.
    • Seed and variation: choose a repeatable set of tone, timing and velocity variations within the limits you set.

    Generation writes an ordinary playable clip. It repeats the generated result; it does not keep inventing a different pattern on every loop. Generate again with a different seed or settings when you want a new version.

    Example: a five-pulse following bassline

    1. Use the unmodified C major triad setup from the chord exercise. Select degree I and set Follower harmony source: Live / selected chord.
    2. Select an empty slot and expand ACCOMPANIMENT.
    3. Set Steps: 16, Pulses: 5, Rotation: 0, Step ticks: 240000 and Gate ticks: 120000. This gives a four-beat loop with sixteenth-note step spacing and shorter notes.
    4. Set Lowest tone: −3 and Highest tone: −3. With this triad voicing, that selects the root one octave below the chord. Set both variation fields to 0 and enable Follow active harmony.
    5. Select Generate selected slot, then launch the clip.
    6. Choose I, VI, IV and V in Harmony. The bass changes from C to A to F to G at subsequent attacks while its five-pulse rhythm continues.
    7. To automate those changes, choose a recorded chord clip under Follower harmony source and launch that clip too.

    For a melodic part, widen the tone range—for example, 0 through 5 spans two sets of triad tones—and choose another seed. The tone numbers refer to positions in the voiced chord, not semitone offsets. Changing chord size or voicing changes what those indices select.

    Generate a clip

    1. Select and stop the target slot. Generation replaces its content and supports Undo.
    2. Choose the desired harmony.
    3. Expand ACCOMPANIMENT · Euclidean rhythm and seeded pitch lane.
    4. Set rhythm, pitch and variation fields.
    5. Optionally enable Follow active harmony.
    6. Select Generate selected slot, then launch it.

    Keep a pattern or make its pitches permanent

    Saving retains the rendered pattern. Freeze current harmony has a more specific purpose: it turns the currently reharmonized result into fixed notes so it no longer needs the changing harmony source.

    • Follow harmony: remap future attacks to current effective harmony while retaining rhythm and expression.
    • Use original notes: disable following and replay the clip's original rendered pitches.
    • Freeze current harmony: write the current following result as fixed pitches. Undo restores the previous clip.
    • Stop the selected clip before changing follow mode or freezing. Freeze a following clip before overdubbing.
    • Held notes retain the pitches chosen at their attacks. A later chord does not retune unrelated sustained voices.

    Use a chord clip as leader

    1. Record a phrase in Chord pads so the clip contains original chord gestures.
    2. Set Follower harmony source to that clip.
    3. Generate or enable following on another clip.
    4. Launch leader and follower.
    • The leader uses recorded harmonic intent, including the source timing before delayed strum/humanized tones.
    • The last leader chord carries across loop pickup gaps. Stopping the leader restores live/selected harmony.
    • An empty slot or a clip without chord gestures falls back to live/selected harmony.
    • Editing rendered note pitches does not rewrite the clip's recorded harmonic intent.
    • Top-row degree selectors take over from the recorded leader; voicing/modifier/articulation selectors also take over the effective harmony.
    8. Record, overdub and recover a phrase

    A clip stores the notes you performed, including chords, timing and expression. Use recording for a new phrase, overdub to add a layer, or retrospective capture when you played something before pressing Record. Quantization is optional.

    OperationUse whenWhat is kept
    Record selectedYou want to start a new phrase now.The new take, after Finish take. An existing clip is replaced on commit.
    OverdubYou want to add notes to an existing loop.The original clip plus the added layer, at the original loop length.
    Capture last 4 beatsYou want to recover a phrase you just played.The recent four-beat performance, including expression.
    Duplicate to nextYou want a separate variation to edit.A copy in the next slot; existing destination content is replaced.

    Record an expressive phrase

    1. In the host, select an empty slot. Confirm its selection marker.
    2. Select Play mode, then Record selected.
    3. Switch to the instrument. Play mouse/keyboard contacts, or select Play scripted phrase for the supplied three-contact gesture.
    4. Release contacts. If using the script, wait for its contacts and release tails to finish.
    5. Return to the host and select Finish take.
    6. Confirm the slot is RECORDED. The note editor shows the recorded polyphonic phrase.
    7. Click the already-selected slot to launch it. Confirm PLAYING and changing MIDI capture output.
    8. Select Stop selected to stop that loop.
    • Recording begins immediately; there is no implicit count-in or quantization.
    • The take length becomes the loop length. Time spent switching windows remains part of that take.
    • New recorded attacks retain free timing, initial expression, subsequent X/Y/Z samples and release information.
    • Notes already sounding before Record are not included as new attacks.
    • If Finish occurs while recorded notes remain held, the stored notes close at the loop end. The live voices retain their independent ownership.
    • Record selected on an existing stopped slot replaces its clip when committed. The previous clip remains available to one-step Undo.
    Finish is required to keep a take. Cancel take and Stop all discard the uncommitted take and retain the previous committed clip. Save rejects an unfinished take.

    Overdub

    1. Select a recorded slot and stop it.
    2. If it follows harmony, use Freeze current harmony before overdubbing.
    3. Select Overdub. The original loop plays while new input is captured.
    4. Play additional notes; select Finish take to merge, or Cancel take to retain the original loop.
    • The original loop length is retained. New attacks fold into it modulo that length.
    • New notes crossing the loop end are truncated there. The old notes and curves retain their exact values.
    • The merged loop resumes at the next boundary relative to the overdub's origin. Finishing mid-cycle may leave a short gap.
    • Undo restores the complete previous clip, not only selected notes.

    Retrospective capture

    1. Play with the native clock running, without starting a take.
    2. Select a stopped target slot.
    3. Select Capture last 4 beats.
    4. Inspect the resulting clip, then launch or save it.
    • Capture uses recent playing that reached the host; it does not stop live notes.
    • Notes crossing the beginning receive their then-current expression. Notes still held close in the captured copy at the end.
    • Generated harmony retains rendered events and its recorded source gestures.
    • History is bounded. An expired or empty window rejects instead of silently creating a partial phrase.
    • Capture may replace an existing stopped clip; Undo restores it.

    Duplicate and Undo

    • Duplicate to next copies the selected clip into the next slot. Slot 08 wraps to slot 01.
    • The destination must be stopped. Existing destination content is replaced; copied notes are retargeted to the destination slot's track.
    • Timing, expression, conditions and parameter locks are retained.
    • Undo is one-step, applies to the last supported clip or learned-bank edit, and is not saved in session files. There is no general multi-step history or Redo control.
    • Undo of a clip edit stops the affected clip before restoring it.
    9. Perform with clips

    Use the clip bank to combine parts during a performance. Each slot has its own phrase and loop length. Start a bassline under a chord loop, bring in a rhythmic part, or drop a part out temporarily. The current application provides live clip launching; it does not assemble these launches into an arrangement timeline.

    Launch grid sets when a newly launched clip starts. Choose four beats to align new parts with four-beat boundaries, or Off for immediate starts. This does not quantize the notes inside a clip.

    Slot selection and launch

    • Click an unselected host slot to select it. Click it again to launch; if it is already playing or queued, the second click stops or cancels it.
    • Controller clip pads launch/stop their slots directly; they do not require the host's two-click selection sequence.
    • Stop selected affects the selected clip. Stop all releases all playback/live voices and cancels an uncommitted take.
    • Clips have independent loop lengths and may play together within the total voice budget.
    Launch gridStart time
    Off · immediateCurrent host musical position.
    1 beatNext whole-beat boundary, or immediately when already on it.
    4 beatsNext multiple of four beats, or immediately when already on it.
    • The preference applies to future launches from host buttons and controller pads.
    • Changing the preference does not reschedule a queued clip.
    • Stop and queued-launch cancellation are immediate.
    • Launch grid survives device reset and session replacement in the current app process. It is not saved; app restart defaults to Off.

    Local tempo

    • Enter Local tempo (BPM), then select Apply tempo.
    • Range: 1–999 BPM, resolution 0.001 BPM.
    • Tempo may change during playback or recording. Clip phase, held expression and queued musical boundaries continue.
    • Recording stores beat positions under the active tempo. The session stores the current tempo, not a tempo-automation map.
    • This control is not external MIDI Clock synchronization.

    Hold mute

    • Launch a clip, select it and hold Hold mute selected.
    • The clip's sounding voices release and future attacks are suppressed. Loop phase continues.
    • Release the control to resume future attacks; notes whose attacks passed while muted do not restart.
    • A muted recorded harmony leader continues supplying its chord progression.
    • Controller equivalent: row 1 above the clip column. Clip and mute pads show cyan while muted.

    Temporary octave

    • Hold Hold octave down or Hold octave up for a selected playing/queued clip.
    • Future attacks shift by −12 or +12 semitones. Already-sounding notes retain pitch, expression and release ownership.
    • Release restores original future pitches. Opposing holds cancel; releasing one leaves the other direction active.
    • Out-of-range pitches reject; notes are not clipped to MIDI endpoints.
    • Stored pitches and Undo history do not change.

    Using several temporary controls

    • Host hold buttons accept pointer hold or focused Space/Enter. Focus loss releases host holds.
    • Host and controller contacts own independent holds. Releasing one does not cancel another still-held source.
    • Stop, mode changes, disconnect and player replacement retire old hold ownership.
    • Latched virtual fingers remain explicit contacts after focus loss. Use Release all when finished.
    10. Add conditional notes and fills

    A condition decides whether a particular note plays on a given loop pass. Use it to make a repeating part vary over time or to add notes only while you hold Fill. The underlying phrase stays available for editing.

    • A note every fourth repetition: choose Loop N of period, set both numbers to 4, and apply. The note plays on repetitions 4, 8, 12 and so on.
    • An extra fill note: choose While Fill held. During playback, hold Fill before that note's next attack to admit it.
    • A note that drops out during a fill: choose While Fill released. Hold Fill to suppress its next attacks.

    Fill does not generate a fill automatically. Prepare the notes and assign their conditions first. Releasing Fill changes eligibility for future attacks; it does not cut off a note that already started.

    1. Stop the selected slot and select a note in the editor.
    2. Choose Playback condition.
    3. For Loop N of period, enter Loop N and Period, then select Apply note condition.
    4. Launch the clip to evaluate the rule.
    ConditionAttack eligibility
    Every loopEvery loop iteration.
    Loop N of periodThe specified one-based iteration in each period. N=4, period=4 admits loops 4, 8, 12, …
    While Fill heldFill is active at the attack timestamp.
    While Fill releasedFill is inactive at the attack timestamp.
    • Loop N and Period range from 1 to 65,535; N must not exceed Period.
    • Each launch restarts counting at loop 1.
    • The rule decides at attack only. Once a note is admitted, its expression and release remain valid even if Fill changes.
    • Skipped attacks emit neither notes nor their parameter locks.
    • Rules are saved with the clip; raw note/curve data remains unchanged. Undo restores previous rules.

    11. Parameter locks and A/B morph: capture only

    These two features control values attached to a performance:

    • Parameter lock: one note carries a specific value when it starts. It can differ from the value attached to the next note.
    • A/B morph: one gesture moves several values together between two stored endpoint sets. For example, one value can rise while another falls.

    In v0.4.0, you can configure, perform, save and inspect these value changes. You cannot use them to change an audible effect, sample position or synthesizer control in the supplied standalone host.

    Capture-only output. Parameter references are backend identifiers, not MIDI CC numbers. These controls produce timestamped diagnostic events. This standalone release provides no audible DSP mapping and does not record parameter automation.

    Per-note parameter lock

    1. Stop the clip and select a note.
    2. Enter Note parameter reference (0–15) and Note parameter value (0–65,535).
    3. Select Apply note parameter.
    4. Launch the clip. Expand A/B MORPH to inspect captured parameter events and their voice IDs.
    • Remove note parameter removes only the entered reference from the selected note.
    • Each admitted attack binds the lock to its new output voice. Other notes retain instrument defaults.
    • Muted or condition-skipped attacks emit no locks.
    • Locks survive moves, quantization, duplication and save/reopen. Overdub preserves old locks; new recorded notes begin without locks.
    • Undo restores the whole previous clip. Up to 16 distinct references may be attached to one note.

    Try two values moving in opposite directions

    1. In A/B MORPH, add destination 1, parameter 1 with State A 0 and State B 65535.
    2. Add destination 1, parameter 2 with State A 65535 and State B 0.
    3. Apply A/B endpoints and move A/B position. The capture display shows one value rising while the other falls.
    4. In Clip pads, slide along the third row from the bottom to operate the same position from the instrument.

    Configure and operate A/B morph

    1. Expand A/B MORPH · parameter capture sink.
    2. Select Add parameter. Set destination, parameter reference and normalized State A / State B values.
    3. Add further endpoints as needed, up to 16. Use unique destination/reference pairs.
    4. Select Apply A/B endpoints.
    5. Use State A, State B or A/B position.
    6. Inspect the captured global parameter values below the controls.
    • Interpolation is linear, rounded to the nearest integer, with exact endpoints. Descending or unchanged endpoint pairs are valid.
    • In Clip pads mode, row 2—the third row from the bottom—controls the same position by X movement.
    • The first finger owns that row until release; firmware slide handovers preserve ownership. Another held contact does not take over.
    • Release leaves the last value. Stop releases notes but does not reset parameter values.
    • After changing endpoints, release and retouch the row.
    • Endpoint pairs persist. Current morph position and backend capabilities do not. Reopen emits no parameter value until an explicit gesture.
    12. Edit notes and timing

    Use the note editor to correct a pitch, move a note earlier or later, or change its length. Expression stays attached to that note. Use attack quantization only when you want a tighter timing grid; it is an explicit edit.

    • Keep free timing: leave the clip unquantized. Recording and reopening do not snap notes to a grid.
    • Tighten the whole phrase: choose an attack grid and quantize. A 1/4-beat grid is sixteenth-note spacing; a 1/2-beat grid is eighth-note spacing.
    • Keep an alternate version: duplicate into an unused next slot before editing. Check the destination first because duplication replaces it.

    Select and edit a note

    1. Select a recorded slot and stop it.
    2. Scroll to NOTE EDITOR.
    3. Select a note bar, or use Previous note/Next note.
    4. Edit Note (MIDI key 0–127), Start ticks and/or Duration ticks.
    5. Select Apply edit. Inspect the note bar and fields.
    6. Use Undo to restore the complete previous clip if required.
    • One beat is a quarter note and equals 960,000 ticks.
    • Moving a note shifts its complete expression curve by the same amount.
    • Repitching changes the MIDI key while retaining expression offsets and values.
    • Shortening removes expression samples at or beyond the new end. Undo restores those samples.
    • The note must fit the clip. Invalid bounds reject before replacing the clip.
    • This editor changes existing notes. It is not an arrangement editor and does not provide a full curve-drawing interface.

    Quantize clip attacks

    1. Stop the selected clip.
    2. Choose Attack grid: 1, 1/2, 1/4, 1/8, 1/16, 1/3 or 1/6 beat.
    3. Select Quantize clip attacks. This applies to every note in the clip, not just the selected note.
    • Attacks move to the nearest feasible grid point measured from clip zero. Halfway ties move later.
    • Each whole lifetime moves: duration, velocity, expression samples, identity, condition and parameter associations remain intact.
    • Near the loop end, a note may move earlier to fit its full lifetime and curve.
    • No note merging, duration quantization or interpolation occurs.
    • Undo restores the original timing. Applying a grid that moves nothing preserves the existing Undo entry.
    • Opening, recording and viewing a clip never quantize it implicitly.
    13. Save, reopen and recover

    Save and reopen

    1. Finish or cancel the current take.
    2. At the bottom of the host, enter an absolute file path whose parent directory exists.
    3. Select Save session. Saving replaces that file.
    4. To load, enter a session path and select Reopen. Save any changes you need before replacing the current session.
    • Reopening validates data before replacement and starts stopped in Play mode.
    • Files are JSON, limited to 8,000,000 bytes. Writes use a temporary sibling, synchronization and atomic rename.
    • Use a persistent directory for retained sessions. The default /tmp/crest-performance-session.json path is temporary.
    • Musical session files, firmware flash fixtures and gesture-run files are different formats.
    SavedNot saved as musical session state
    Tracks, instrument references, slots, loop lengths, raw notes and expression.Active live contacts and voices; playing/queued state.
    Harmony settings, learned bank, harmony source, generating gestures/settings/seeds/algorithm versions.Current Fill, mute and temporary octave holds; Undo history.
    Note conditions, per-note parameter locks and A/B endpoints.Current morph position, emitted parameter history and backend capability declarations.

    Opening an older session

    • Supported older files load without silently quantizing their notes or removing expression.
    • Keep the original file if you need to return to an older application version. Saving from the current version may make that copy unreadable by older versions.
    • See Appendix E for exact file-version compatibility.

    Device reset and failure

    • Reset device restarts the worker, clears stale contacts/scripts and restores ordinary playing.
    • Committed clips, host configuration and current tempo survive a normal device reset. Reset is not a session-save operation.
    • A worker or queue failure disconnects/silences the replica. Reset before accepting new performance input.
    • Finish or cancel takes before normal reset or mode operations. Do not rely on an unfinished take being saved by the standalone UI.

    14. Sound and instrument compatibility

    Choose a sound in the receiving instrument

    The standalone desktop has no connected sound generator, instrument browser or bundled patches. It lets you create and inspect a MIDI performance. For audible playing, connect the virtual device and the command-line host to a separate compatible instrument using Appendix B.

    • A lead, bass, pad or other sound comes from that receiving instrument. The performance features generate notes; they do not select a sound category automatically.
    • For independent bends, pressure and tone changes on simultaneous notes, use an MPE-compatible instrument and patch.
    • An ordinary polyphonic instrument can play chords, but does not provide the same independent expression. Choose its output profile explicitly.
    • The output profile configures message behavior. Changing it does not connect an audio device or load a synthesizer.

    Destination profiles

    1. Finish/cancel recording. Stop all clips and release live contacts and sustain.
    2. Expand OUTPUT · explicit MIDI destination profiles.
    3. Select a destination, profile and valid channel/range values.
    4. Select Apply output profile. Inspect the reported capabilities.

    Appendix B. MIDI ports and command-line host

    Expose virtual firmware to another host

    Start a separate simulator process in OS MIDI mode:

    LINNSTRUMENT_VIRTUAL_MIDI=1 ./linnstrument-sim
# Source checkout:

    • OS MIDI mode is a connection mode, not an external MIDI Clock synchronization feature.
    • CoreMIDI round trips were tested on macOS. Linux OS-port runtime and physical USB behavior are not qualified by the standalone desktop package tests.

    • For a physical device, configure lower MPE, members 2–16 and ±48 semitones before connection. Physical qualification remains separate.

    Keyboard mapping

    1. Release all contacts.
    2. Expand Keyboard contacts.
    3. Edit the JSON mapping and select Apply keyboard settings. Load defaults restores the default mapping.
    {
  "pads": {
    "a": { "x": 3, "y": 2 },
    "s": { "x": 4, "y": 2 },
    "d": { "x": 5, "y": 2 }
  },
  "pressure_down": "[",
  "pressure_up": "]"

    • Map 1–32 lowercase letter/digit keys; the concurrent-contact limit remains 16.
    • Coordinates may be fractional. Row 0 is the bottom; row 7 is the top. Column 0 is the firmware control column. Playing columns are 1–25 or 1–16.
    • Pressure keys must be distinct and must not also be pad keys.

    Built-in and custom contact scripts

    • Play scripted phrase runs the bundled three-contact expressive gesture using the native scheduler.
    • Release existing contacts before starting a script. Resume the native clock if paused. Manual contact commands are rejected while the script owns the surface.
    • Start recording in the host first if the result should become a clip.
    • Scripted contacts continue across window focus changes. Release all cancels the script and its contacts.
    • For a custom script, expand Capture / replay gesture run, enter a path under Custom contact script and select Run script.

    Minimal version-1 contact script for the 200-pad model:

    {
  "version": 1,
  "model": 200,
  "steps": [
    {"at_us": 0, "action": {
      "type": "contact", "id": 1, "x": 4, "y": 2,
      "z": 0.5, "latched": true
    }},
    {"at_us": 300000, "action": {
      "type": "contact", "id": 1, "x": 4.2, "y": 2.1,
      "z": 0.7, "latched": true
    }},
    {"at_us": 600000, "action": {"type": "release", "id": 1}}
  ]
}
    • at_us is relative microsecond time, nondecreasing and at most 60,000,000.
    • A repeated contact ID updates that contact. release removes one; release_all removes all.
    • Every contact must be released before the scenario ends.
    • Maximum: 4096 steps, 1,000,000-byte file, 16 concurrent contacts. IDs must fit nonnegative signed 32-bit range.
    • The script's model must match the running device. Coordinates must fit its sensor surface; Z is 0–1.
    • Steps update contacts at native timestamps. Use sufficiently spaced intermediate steps for scripted motion; pressure envelopes use their separate 1 ms native sampling.

    Capture and verify a manual run

    1. Reset the device before the run to start a new bounded trace.
    2. Perform the required gestures and host actions.
    3. Release all contacts, stop the host and select Pause.
    4. Set Run path and select Export run.
    5. Select Verify replay. Check the reported verified-step count or error.
    • Replay creates another firmware worker; it does not replace the active musical session.
    • The trace contains native commands, timestamps, firmware MIDI, LED changes, snapshot hashes and fixture provenance.
    • Verification compares exact MIDI, LEDs, time and peripheral observations with the captured run.
    • The run buffer is limited to 50,000 steps with an additional byte budget. A full buffer is reported; reset before another complete run. This is not an unlimited performance recorder.
    • Step 10 ms advances paused emulated time. Resume returns to native real-time operation. Browser painting does not drive the sensor clock.

    Read the diagnostic boundaries

    • Firmware / MPE inspector: firmware revision, emulated time, ADC reads, sensor selections, LED writes, active contacts and raw serial output with microsecond completion times.
    • Host capture: output MIDI after library behavior and destination allocation. Member channels may differ from firmware input.
    • Parameter capture: separate global or voice-scoped parameter events; these are not MIDI bytes.
    • Contact rings show input state; LED dots show firmware display state. Neither alone establishes audible sound-engine behavior.
    • The inspector does not provide a full per-note expression plot. Use traces and acceptance fixtures for detailed comparisons.

    Dependencies and ownership

    Minimal engine lifecycle

    use crest_performance_core::{
    API_VERSION, BeatTime, Engine, Limits, Session,
};

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let mut engine = Engine::new(API_VERSION, Session::default(), Limits::default())?;
    engine.advance(BeatTime(0))?;
    let snapshot = engine.snapshot();
    let session = engine.save_session()?;
    assert_eq!(snapshot.active_voices, 0);
    session.validate()?;
    Ok(())
}
    1. Construct and validate the engine with API 13 and a compatible session.
    2. Advance to an input timestamp before accepting input at that exact timestamp.
    3. Drain scheduled note output regularly. Drain parameter output separately when supported.
    4. Apply commands at the current engine position.
    5. Read snapshots, edit clips and serialize sessions on a control thread.
    Contract itemMeaning
    BeatTimeUnsigned 64-bit ticks; 960,000 per quarter note. No implicit quantization.
    NoteKeySource + track + note identity, independent of MIDI channel.
    VoiceIdFresh output identity for live attacks and each loop iteration.
    ExpressionPitch in millionths of a semitone; pressure/timbre in unsigned 16-bit full range.
    OrderingAdvance processes inclusively. Equal-time live input follows scheduled work and preserves caller order. Across players, releases precede attacks. Recorded internal event order is retained.
    Parameter orderingMerge by timestamp, with parameter events before notes at equal time. Apply voice-scoped locks only to the matching VoiceId.

    Capacity, recovery and capabilities

    • On output capacity failure, drain and retry the same advance target. Earlier events may already have committed; the rejected event has not.
    • Stop preflights releases and may require a drain/retry. Do not discard releases to keep processing attacks.
    • Advertise only supported per-destination expression and parameter capabilities. Stored parameter references are not evidence of backend support.
    • checkpoint_session() and checkpoint_session_at(cutoff) provide a saved prefix of an interrupted take without stopping live ownership. The host owns checkpoint cadence, durable files and recovery UI.
    • CaptureRecentAt captures accepted history at an explicit host cutoff without moving the input engine clock.
    • UI, serialization, clip edits and snapshots belong outside a real-time audio callback. The standalone scheduler is not an audio-callback template.
    • One local host clock is implemented here. External MIDI Clock authority, position synchronization and loss recovery remain unimplemented.

    Appendix E. Release versions, limits and sources

    Version handling

    • v0.4.0 writes core session schema 10 inside host envelope 2.
    • v0.3.0 uses the same persistence formats; its public Rust API is 12 rather than 13.
    • Core schemas 1–9 migrate in memory without rewriting their source files or quantizing events.
    • Old host envelope 1 and plain library sessions load at 120 BPM; plain sessions receive lower-MPE output defaults.
    • Unknown versions and incompatible fields reject. Missing required version-2 tempo data rejects rather than silently defaulting.
    • Explicit Save writes current formats. Older readers may reject the result. Keep original files for rollback; changing a version number by hand is not migration.
    • Rendered generated events remain authoritative. Opening an older generated clip does not regenerate it with a newer algorithm.

    Qualification boundaries

    • Release acceptance covers firmware-backed virtual playing, independent expression, recording/reopening, looping, controller launching and decoded LED feedback on tested profiles.
    • The sensor model uses ideal synthetic fixtures. Physical sensor noise, tactile response, calibration accuracy, scanning latency and USB electrical behavior are not established by it.
    • SteamOS packaging, Deck controls, audio configuration, suspend/resume and physical-device workflow remain unqualified.
    • There is no standalone sample/granular DSP, plugin host, arrangement editor, parameter-automation recorder or external MIDI Clock follower in v0.4.0.
    • Production sound generation belongs to the consuming host. Crest Synth integration and production parameter mappings are not implied by event-level tests.
